## Algorithms & Verification Approach

### Audit Checklist

1. **POST /query handler location:**
   - Typically in `agent/src/main.py` or `agent/src/routes/query.py`.
   - Verify handler calls `process_question(question)` directly (blocking).
   - Confirm no async/await wrapper that alters behavior from pre-Story-1 state.

2. **GET /health handler location:**
   - Typically in `agent/src/main.py` or `agent/src/routes/health.py`.
   - Verify handler returns `{"status": "ok"}`.
   - Confirm no dependency on run store or new agent routes.

3. **Tool names and MCP integration:**
   - Search codebase for tool name definitions (if any).
   - Search for `MCP_URL` or MCP configuration.
   - Confirm these are unchanged from pre-Story-1 state.

4. **ID normalization:**
   - If any query/question ID normalization exists (e.g., slugification), verify it is unchanged.
   - No new normalization logic introduced.

5. **Process isolation:**
   - Verify `process_question` is called only from the main agent process.
   - No child processes or thread pools spawned for MCP calls.
   - Confirm Stories 1–2 do not fork or thread.

### Regression Test Categories

**Category A: Blocking Behavior**
- `POST /query` with valid question blocks until `process_question` completes.
- Measure latency; confirm no regression compared to baseline.

**Category B: Response Format**
- `POST /query` returns `{"answer": "..."}` or `{"error": "..."}` as JSON.
- `GET /health` returns `{"status": "ok"}`.

**Category C: Coexistence**
- Both `POST /agent/query` (new, non-blocking) and `POST /query` (existing, blocking) work in same session.
- No global state corruption or route collision.

**Category D: MCP Isolation**
- MCP is called only from main process (no child processes).
- Tool names and configuration unchanged.

## Risks

| Risk | Impact | Severity | Mitigation |
|------|--------|----------|-----------|
| **New agent routes interfere with existing query route** | POST /query blocked or behaves unexpectedly. | Medium | Share the same FastAPI app instance; confirm no middleware or global state corruption. Test both endpoints in the same session. |
| **process_question called from multiple threads/tasks** | Race condition or concurrent state mutation. | Medium | Verify `process_question` is only called from the main agent process (no child processes or threads). Both endpoints call it from the same context. |
| **MCP_URL or tool names changed elsewhere** | PER-20 contract breaks. | High | Audit codebase for any changes to `MCP_URL`, tool definitions, or id normalization. Confirm this ticket does not modify any of those. |
| **Latency regression on POST /query** | Performance regression hidden by new async infrastructure. | Medium | Measure baseline latency of `POST /query` before Tickets 1–2 are merged. Assert no change in test suite (10% tolerance for normal variance). |
