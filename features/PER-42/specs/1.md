## Schema & API Contracts

### Request Model

```python
# Request body
POST /agent/query
{
  "query": "<non-empty string>"
}
```

**Validation:**
- `query` must be present.
- `query` must not be `None`, empty string, or whitespace-only.
- Pydantic validation errors (HTTP 422) are caught by custom exception handler and converted to HTTP 200 `{"status": "rejected", "agent_run_id": "<id>", "reason": "invalid query"}` before handler body executes.

### Response Models

**Acceptance (HTTP 200):**
```json
{
  "status": "ok",
  "agent_run_id": "<uuid v4 hex>"
}
```

**Rejection (HTTP 200):**
```json
{
  "status": "rejected",
  "agent_run_id": "<uuid v4 hex>",
  "reason": "invalid query"
}
```

### Behavior Contract

1. **Input validation** occurs synchronously before any async work.
2. **HTTP 200 response** is sent immediately (before `process_question` is invoked or completes).
3. **No LLM or MCP calls** on rejection; background job is not spawned.
4. **agent_run_id is generated in both cases** (acceptance and rejection); same id is used in downstream SSE stream.
5. **Pydantic validation errors** (HTTP 422 from missing or non-string `query`) are caught and converted to HTTP 200 rejected response before handler body executes.

### Run Store Interface (`agent/src/agent/run_store.py`)

```python
from dataclasses import dataclass
from typing import Optional
from asyncio import Queue
import uuid
import time

@dataclass
class Run:
    """Single agent run."""
    id: str                              # agent_run_id (UUID v4 as hex string)
    query: str
    created_at: float                    # Unix timestamp
    status: str                           # "pending", "completed", "failed"
    events: Queue                        # asyncio.Queue for event messages
    result: Optional[dict] = None        # {"answer": "…"} or {"error": "…"}
    started_at: Optional[float] = None
    ended_at: Optional[float] = None
    in_progress_sent_at: Optional[float] = None

class RunStore:
    """In-memory registry of active runs."""
    
    def __init__(self):
        self._runs: dict[str, Run] = {}
    
    async def create(self, query: str) -> Run:
        """Generate unique agent_run_id, create Run, enqueue in_progress event, return Run.
        
        Returns: Run object with id, events queue pre-populated with in_progress event.
        The in_progress event is enqueued synchronously before this method returns.
        """
        run_id = uuid.uuid4().hex
        now = time.time()
        
        run = Run(
            id=run_id,
            query=query,
            created_at=now,
            status="pending",
            events=Queue(),
            in_progress_sent_at=now
        )
        
        self._runs[run_id] = run
        
        # Enqueue in_progress event immediately
        await run.events.put({
            "event": "in_progress",
            "data": {"run_id": run_id}
        })
        
        return run
    
    async def get(self, run_id: str) -> Optional[Run]:
        """Retrieve Run by agent_run_id; return None if not found or expired."""
        return self._runs.get(run_id)
    
    async def enqueue_event(self, run_id: str, event_type: str, data: dict) -> None:
        """Append event to run's queue for SSE delivery.
        
        Args:
            run_id: agent_run_id
            event_type: "in_progress", "completed", or "failed"
            data: JSON-serializable dict with run_id and result/error
        """
        run = self._runs.get(run_id)
        if run:
            await run.events.put({"event": event_type, "data": data})
    
    async def mark_failed(self, run_id: str, reason: str) -> None:
        """Mark rejected run as failed; enqueue failed event.
        
        Called during AC-2 rejection path (invalid input) to enqueue the failed event.
        The in_progress event was already enqueued by create().
        Both events are now queued in run.events for SSE delivery.
        """
        run = self._runs.get(run_id)
        if run:
            run.status = "failed"
            await run.events.put({
                "event": "failed",
                "data": {"run_id": run_id, "error": reason}
            })
    
    async def cleanup_expired(self, ttl_seconds: int = 3600) -> None:
        """Delete runs older than ttl_seconds (deferred to Story 2)."""
        pass
```

from fastapi import FastAPI, HTTPException
from fastapi.exceptions import RequestValidationError
from agent.models import AgentQueryRequest, AgentQueryAccepted, AgentQueryRejected
from agent.run_store import RunStore
from agent.background_task import run_background_job
import asyncio

app = FastAPI()

# Global singleton run store
run_store = RunStore()

# Custom exception handler: convert HTTP 422 (Pydantic validation error) to HTTP 200 rejected response
@app.exception_handler(RequestValidationError)
async def validation_exception_handler(request, exc):
    """Convert Pydantic validation errors to HTTP 200 rejected response."""
    # Generate agent_run_id for the failed validation
    run = await run_store.create("")
    await run_store.mark_failed(run.id, "invalid query")
    return {
        "status": "rejected",
        "agent_run_id": run.id,
        "reason": "invalid query"
    }

@app.post("/agent/query", response_model=AgentQueryAccepted | AgentQueryRejected)
async def post_agent_query(req: AgentQueryRequest) -> AgentQueryAccepted | AgentQueryRejected:
    """
    Accept a user query immediately and return agent_run_id.
    
    - AC-1: Return HTTP 200 immediately without waiting for process_question.
    - AC-2: Reject if query is missing or empty/whitespace-only; do not spawn background job.
    """
    query = req.query.strip()
    
    if not query:
        # Rejection path (AC-2)
        run = await run_store.create("")
        await run_store.mark_failed(run.id, "invalid query")
        return AgentQueryRejected(
            status="rejected",
            agent_run_id=run.id,
            reason="invalid query"
        )
    
    # Acceptance path (AC-1)
    run = await run_store.create(query)
    asyncio.create_task(run_background_job(run.id, query, run_store))
    return AgentQueryAccepted(status="ok", agent_run_id=run.id)

## Algorithm Notes

### Input Validation

1. Receive `AgentQueryRequest` with `query` field.
2. FastAPI automatic validation (Pydantic):
   - Rejects if `query` field is missing → 422 Unprocessable Entity (caught by custom exception handler).
   - Rejects if `query` is empty string (`""`).
   - Rejects if `query` is `None`.
3. **Custom validation in handler:** Strip whitespace; if result is empty, treat as invalid.
4. **Custom exception handler:** Converts HTTP 422 (validation error) to HTTP 200 rejected response before handler body executes.
5. **Response contract:** HTTP 200 for both acceptance and rejection (per AC-1, AC-2); never 422 returned to caller.

### Acceptance Path (AC-1)

1. Input passes validation (non-empty after strip).
2. Call `run_store.create(query.strip())`:
   - Generate `agent_run_id` as UUID v4 hex string (32 chars, globally unique).
   - Create `Run` object with status `"pending"`.
   - Create `asyncio.Queue` for events.
   - Record `in_progress_sent_at = time.time()`.
   - Enqueue `in_progress` event with data `{"run_id": agent_run_id}` (synchronous).
   - Store `Run` in `_runs` dict keyed by `agent_run_id`.
   - Return `Run` object.
3. Spawn background job: `asyncio.create_task(run_background_job(run.id, query.strip(), run_store))`.
   - **Critical:** Do not `await` this call; return immediately.
   - Background task will call `process_question` asynchronously (implementation deferred to Story 2).
4. Return HTTP 200 `AgentQueryAccepted(status="ok", agent_run_id=run.id)`.

### Rejection Path (AC-2)

1. Input fails validation (empty or whitespace-only `query`, or Pydantic validation error caught by exception handler).
2. Call `run_store.create("")`:
   - Generate `agent_run_id` as UUID v4 hex string.
   - Create `Run` object with status `"pending"`.
   - Record `in_progress_sent_at = time.time()`.
   - Enqueue `in_progress` event with data `{"run_id": agent_run_id}` (synchronous).
   - Store in `_runs` dict.
   - Return `Run` object.
3. Call `run_store.mark_failed(agent_run_id, "invalid query")`:
   - Update run status to `"failed"`.
   - Enqueue `failed` event with data `{"run_id": agent_run_id, "error": "invalid query"}` (synchronous).
   - Both events (`in_progress` and `failed`) are now queued in `run.events`.
4. **Do NOT spawn background job; do not call `process_question`.**
5. Return HTTP 200 `AgentQueryRejected(status="rejected", agent_run_id=run.id, reason="invalid query")`.
6. **Note:** When `GET /agent/runs/{agent_run_id}/events` is called (Story 2), the SSE handler reads both events from the queue and delivers them to the subscriber. No separate invocation of `process_question` occurs for rejected runs.

### ID Generation

- Use `uuid.uuid4().hex` → 32-character lowercase hex string (e.g., `"a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4"`).
- Collision probability: negligible (< 2^-120 for < 1 billion IDs).
- No locking required; UUID v4 generation is thread-safe.

### Error Handling

- **Pydantic validation error (AC-2):** Caught by custom exception handler; generates rejected run with failed event before handler body executes.
- **Handler-level validation error (AC-2):** Caught by post_agent_query; calls mark_failed() before returning.
- **Unhandled exception in POST handler:** Bubbles up to FastAPI; returns HTTP 500 by default. Story 2 wraps background job in try/except to emit `failed` events on exceptions.

## Risks

| Risk | Impact | Severity | Mitigation |
|------|--------|----------|-----------|
| **Synchronous validation blocks request thread** | High-latency requests pile up; poor throughput. | Medium | Validation is O(1) string check; negligible. Keep validation synchronous. |
| **In-memory run store grows unbounded** | Memory leak; OOM crash. | High | Implement TTL-based cleanup (delete runs 1 hour after completion). Log policy in startup. |
| **agent_run_id collision** | Two runs share same id; events corrupt. | High | Use UUID v4 (collision probability < 2^-120). Do not use sequential integers without locking. |
| **Background task never spawned** | Job runs but no result is ever published. | High | Test that spawn completes before HTTP return; verify in unit tests. |
| **PER-20 signature changes** | Incompatible call to `process_question`. | High | PER-20 is in scope for AC-6; lock contract in integration tests. |
| **Exception in background task silently swallowed** | Job fails without emitting error event; stream never closes. | Medium | Wrap background task in try/except; emit `failed` event on any exception. Log to stderr. |
| **Multiple POST requests generate duplicate agent_run_ids** | Two jobs compete for same run slot. | Low | UUID v4 collision probability is negligible; no locking required. |
| **Pydantic validation not converted to 200 response** | HTTP 422 returned to caller, violating AC-1 contract. | High | Custom exception handler converts 422 to 200 rejected response before handler body executes. |

## Notes

- **No auth required.** Out of scope per AC-6 and requirements.
- **No rate limiting.** Assume upstream FastAPI middleware.
- **UUID v4 collision safety:** Safe for up to billions of runs.
- **Synchronous validation:** O(1) string check; no async overhead; validation happens before task spawn.
- **Background job spawn:** Via `asyncio.create_task()`; does not block request handler or await completion.
- **Event enqueue on rejection:** `in_progress` and `failed` events enqueued to `run.events` (an `asyncio.Queue`) synchronously before POST returns. Story 2 SSE stream handler reads these queued events when `GET /agent/runs/{agent_run_id}/events` is called (see Story 2 for event delivery).
- **PER-20 dependency:** `process_question(query: str) → dict` signature is fixed (AC-6). Any future change must preserve return type: `{"answer": "<text>"}` or `{"error": "<message>"}`.
- **Run store lifecycle:** Runs are created and stored in memory. Cleanup (TTL-based expiration) deferred to Story 2. No persistence layer; in-memory queue is sufficient for PoC.
- **Routes location:** Per `change_requests.md`, all routes (POST /agent/query, GET /agent/runs/{id}/events, existing POST /query and GET /health) are registered in `agent/src/main.py`. No separate routes module or file.
- **Pydantic validation handling:** Custom exception handler catches HTTP 422 from Pydantic validation (missing or non-string `query`) and converts to HTTP 200 rejected response before POST handler body executes. This ensures AC-1 and AC-2 contract for HTTP 200 responses is honored.

## Open Questions

1. **Should agent_run_id be a UUID or sequential integer?**
   - Decision adopted: UUID v4 for simplicity and collision-safety.

2. **How long should runs persist in the store?**
   - Adopted: 1 hour TTL after completion/failure (configurable via env var in Story 2).

3. **Should rejected runs generate SSE events or just reject at POST?**
   - Decision: Rejected runs generate `in_progress` and `failed` events immediately, which are enqueued synchronously before POST returns. SSE stream (Story 2) delivers them when `GET /agent/runs/{agent_run_id}/events` is called.

4. **Does validation accept leading/trailing whitespace as valid query?**
   - Decision: `.strip()` before validation; whitespace-only is rejected per AC-2.

5. **Should the POST handler log the query or agent_run_id?**
   - Decision: Log agent_run_id and status ("ok" | "rejected") at INFO level; log query only at DEBUG.
